# Upgrading to 4.0.0

4.0.0 has two breaking changes:

- [JSX a11y rules move to a new plugin](#jsx-a11y-rules-move-to-a-new-plugin): rename `jsx-a11y/` references. Most
  projects only need the command in step 2.
- [`reset.d.ts` changes three type overrides](#resetdts-changes-three-type-overrides): only affects projects importing
  `@signmax/config/reset.d.ts`, and in most of them nothing needs to change.

## JSX a11y rules move to a new plugin

The JSX accessibility rules now come from
[`eslint-plugin-jsx-a11y-x`](https://github.com/eslint-community/eslint-plugin-jsx-a11y-x) instead of
[`eslint-plugin-jsx-a11y`](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y). The original has not released since
October 2024 and still declares eslint 9 as its upper bound. The fork is maintained under the `eslint-community` org and
supports eslint 10.

The rule **IDs** change from `jsx-a11y/*` to `jsx-a11y-x/*`. The rules themselves do not:

- The same 34 rules are enabled, with the same severities and options, on the same files (`**/*.tsx`, `**/*.jsx`).
- Existing code reports the same violations. Only message wording and the linked doc URLs differ.
- Nothing to install or uninstall: the plugin ships as a dependency of `@signmax/config`, as before. Peer dependencies
  are unchanged.

### Do I need to do anything?

Only if your project mentions the old namespace. Check from the repository root:

```sh
git grep -nE '(^|[^[:alnum:]_-])jsx-a11y/|["'\'']jsx-a11y["'\''][[:space:]]*:'
```

No output means nothing to do beyond bumping the version.

### Steps

#### 1. Bump the package

```sh
pnpm add -D @signmax/config@^4.0.0
```

#### 2. Rename rule references

This rewrites every `jsx-a11y/<rule>` to `jsx-a11y-x/<rule>` in `eslint-disable*` comments, inline `/* eslint … */`
comments and rule overrides in your `eslint.config.*`. It leaves `eslint-plugin-jsx-a11y/…` import paths and URLs alone,
and running it twice is harmless.

```sh
git grep -lzE '(^|[^[:alnum:]_-])jsx-a11y/' -- '*.js' '*.jsx' '*.ts' '*.tsx' '*.mjs' '*.cjs' '*.mts' '*.cts' \
  | xargs -0 perl -pi -e 's{(?<![\w-])jsx-a11y/}{jsx-a11y-x/}g'
```

Review the diff before committing.

#### 3. Rename the `settings` key

Only relevant if your `eslint.config.*` maps custom components (`components`), attributes (`attributes`) or polymorphic
props (`polymorphicPropName`, `polymorphicAllowList`) for the a11y rules. Rename the key by hand:

```diff
 settings: {
-  "jsx-a11y": { components: { Image: "img" } },
+  "jsx-a11y-x": { components: { Image: "img" } },
 },
```

The old key is **silently ignored**, so skipping this step does not fail. Instead `<Image>` and friends stop being
checked as the DOM elements they render.

#### 4. Drop the three removed rules

`accessible-emoji`, `label-has-for` and `no-onchange` do not exist in the fork. They were deprecated upstream and never
part of this config, so they only matter if you enabled one yourself. Remove those entries.

#### 5. Run ESLint

```sh
pnpm exec eslint .
```

### What a missed reference looks like

Checked against eslint 10.14.0:

| leftover                                                                  | result                                                                                                                        |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `// eslint-disable… jsx-a11y/<rule>` or `/* eslint jsx-a11y/<rule>: … */` | lint error `Definition for rule 'jsx-a11y/<rule>' was not found`, **and** the violation it suppressed is reported again       |
| `"jsx-a11y/<rule>": "warn"` / `"error"` in `eslint.config.*`              | ESLint exits before linting: `A configuration object specifies rule "jsx-a11y/<rule>", but could not find plugin "jsx-a11y".` |
| `"jsx-a11y/<rule>": "off"` in `eslint.config.*`                           | accepted without error, but turns nothing off — the rule now runs as `jsx-a11y-x/<rule>`                                      |
| `settings["jsx-a11y"]`                                                    | silently ignored (step 3)                                                                                                     |
| a removed rule under `jsx-a11y-x/`                                        | ESLint exits: `Could not find "<rule>" in plugin "jsx-a11y-x".`                                                               |

## `reset.d.ts` changes three type overrides

`@signmax/config/reset.d.ts` used to import `@total-typescript/ts-reset` 0.6.1. That package is now vendored into this
one, at the unreleased 0.7.0 (npm never got it), so `@total-typescript/ts-reset` is no longer installed. Every other
override (`JSON.parse` and `res.json()` returning `unknown`, `Array.isArray` narrowing to `unknown[]`, widened
`includes`/`has`/`indexOf`, `new Map()` as `Map<unknown, unknown>`, `localStorage.x` as `unknown`) is unchanged.

| change                                               | effect on your code                                                                                                                                                                                                                                      |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `promise-catch` removed                              | `.catch()`/`.then()` on a `Promise<A> \| Promise<B>` union **compiles again** (it was `TS2349: This expression is not callable`). The rejection `reason` is `any` again instead of `unknown`, so code that narrowed it keeps working; nothing new fails. |
| `.filter(Boolean)` written inline as a call argument | the array elements are **checked against the parameter type again**. 0.6.1 silently skipped that check, so a wrong element now surfaces as a type error. This is the one change that can produce new errors, and each one is a real bug.                 |
| `cloneNode()`                                        | returns the element's own type (`HTMLDivElement`) instead of `Node`. A cast like `el.cloneNode() as HTMLDivElement` becomes redundant but still compiles.                                                                                                |

If you import `@total-typescript/ts-reset` yourself next to `@signmax/config/reset.d.ts`, remove that import and the
dependency. Importing its `recommended` or `dom` entrypoint brings 0.6.1's `promise-catch` back. To keep `unknown` for
rejection reasons deliberately, install `@total-typescript/ts-reset` and import only
`@total-typescript/ts-reset/promise-catch`.
